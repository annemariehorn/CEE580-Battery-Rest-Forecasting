# Design decisions

Each entry: what we decided, why, and when. Add to this as the project develops;
it feeds directly into the "Preprocessing" and "Methods" sections of the reports.

| Date | Decision | Reason |
|---|---|---|
| Oct 9 | Use four NASA cells (B0005, B0006, B0007, B0018) | Free, documented, clean; rest gaps are visible in the timestamps |
| Oct 9 | B0018 is the main test battery | B0005–B0007 were cycled side by side with nearly identical schedules (capacity correlation 0.98–0.998); only B0018 is independent |
| Oct 9 | End of life = first measurement below 1.5 Ah (25% fade) | B0007 never reaches NASA's 1.4 Ah criterion (minimum 1.4005 Ah); capacity can bounce back after rests, so use the first crossing (B0006 recovers above 1.5 Ah until measurement 92) |
| Oct 9 | Forecast origins 30, 45, 60; horizons 1–50; score horizons 20–50 | All origins precede B0018's end of life (measurement 70); 20–50 tests longer-range forecasting, where rest effects might matter |
| Oct 9 | Dropped the Gaussian process | Unstable and overconfident in a pilot with four batteries; not needed for the hypothesis |
| Nov | Rest time = gap since previous discharge **ended**, minus recorded operation durations | The first approach (gap between discharge starts) counted charging time as rest. Impedance tests have no recorded duration, so the estimate is an upper bound |
| Nov | Future rest treated as an **oracle** input | Recorded rest times were not necessarily planned in advance; the oracle measures the most that rest information could help |
| Nov 14 | Models predict the capacity *change* from the origin, then add current capacity back | Batteries start at different capacities (1.86–2.04 Ah); the change transfers across batteries better than the level |
| Nov 14 | Trend baselines fit the last 20 measurements | Long enough to average out single jumps; short enough to follow recent fade. Sensitivity to this window still to be checked |
| Nov 26 | Ridge alpha = 3000 for all three settings | Lowest mean RMSE holding out each of B0005–B0007 in turn (57.8 mAh; alpha = 1000 gives 57.9, so the choice is not sensitive). One alpha for all settings so they differ only in rest inputs. B0018 not used |
| Nov 26 | Ridge uses log(1 + rest hours); alpha = 1000 | With raw hours, one 241 h rest dominates a linear model; capacity recovery levels off with longer rests. The log form was also suggested by the proposal's exploratory analysis, which itself used B0018 (a linear model on log rest, trained on B0005–B0007, explained 79% of B0018's cycle-to-cycle change), and the change was made after a first B0018 evaluation with raw hours. alpha was chosen on B0005–B0007 only (mean validation RMSE across settings 55.1 vs 57.8 mAh for raw hours). So B0018 is held out from model FITTING but not fully independent of model-DEVELOPMENT decisions; the log-rest result is exploratory. Both B0018 results are reported (`ridge_raw_rest` and `ridge`) |
| Nov 26 | Uncertainty: paired moving-block bootstrap, blocks of 10 horizons within each origin, 2000 draws, 95% percentile interval for 1 − RMSE_B/RMSE_A | Neighbouring horizons have correlated errors, so single-error resampling would give intervals that are too narrow; pairing uses the same rows for both settings. Block lengths 5 and 15 give similar intervals. Intervals reflect uncertainty over B0018's forecasts only, not over which battery is tested |
| Nov 26 | Robustness checks reported alongside, not instead of, the main design (B0018; origins 30/45/60; horizons 20–50) | The main design was fixed in the proposal; switching to a more favourable origin or horizon window after seeing results would be cherry-picking. Checks: each battery held out, every 5th origin 20–80, horizon windows 1–20/20–50/1–50 |
| Nov 26 | Add a cautious bootstrap (blocks of predicted measurements) and report it next to the within-origin one; add future-vs-past-rest comparison; input checks in the bootstrap | Review (ChatGPT) noted that origins overlap in the measurements they predict, so the within-origin bootstrap can understate uncertainty. The cautious interval for future rest vs capacity only is −1.7 to 52.5% (block 10), so the improvement is described as large and consistent in direction but uncertain in size. Future vs past rest isolates the effect of future rest, since the future-rest setting also contains past rest. Raw event order checked: no overlapping operations (test added) |
| Nov 26 | Rest-duration sensitivity: assume 0, 15 or 32 min per impedance test, subtract from each rest (floor 0); alpha fixed at 1000 | The next operation starts a median 32.0 min (10th percentile 31.8, minimum 14.7) after an impedance test begins, so 32 min is the TYPICAL time available per test, not a bound for every test (see next row for per-test caps); 60 min was dropped as inconsistent with the timestamps. Capacity-only predictions are checked to be identical across scenarios. At 32 min, median rest for B0005–B0007 falls from 1.11 h to 0.05 h (similar to B0018); long rests are almost unchanged |
| Nov 26 | Rest-duration scenarios cap each test at its own timestamp window: subtract min(assumed minutes, window) per test | Review (ChatGPT, third round): 32 min is the typical window, not a bound for every test (minimum 14.7 min; 61.7% of windows are just under 32 min). With per-test caps the 32-min result is 15.4% (future vs capacity) and 8.8% (future vs past), essentially unchanged. Primary result stays at 0 min (original upper-bound estimates); 15 and 32 min are sensitivity scenarios. Robustness checks use the original estimates |
| Nov 26 | Conclusion wording for the report (after third review) | "Using log-transformed future-rest information reduced ridge RMSE on held-out battery B0018 by 27.9% under the original rest-time estimates. Under alternative assumptions about unrecorded impedance-test durations, the observed improvement decreased (to 23.2% and 15.4%), showing sensitivity to how rest was measured. Although the point estimates remained positive across the evaluated scenarios, the approximate 95% target-block bootstrap sensitivity intervals included zero, so the magnitude and reliability of the improvement remain uncertain. Exploratory robustness analyses using the original rest estimates showed improvements on all four batteries and at most evaluated forecast origins. Past-rest information alone provided limited overall benefit. Because the log-rest refinement followed an initial evaluation on B0018 and future rest times were supplied retrospectively, these findings are exploratory evidence of predictive usefulness under an oracle-information setting rather than proof of a generalizable or operational improvement." |
| Nov 26 | Unit of evaluation is the origin–horizon forecast (93 per model and setting), not an independent measurement | Origins overlap, so some measurements are scored up to three times; this matches the proposal's design and is stated so the effective sample size is not overstated |
